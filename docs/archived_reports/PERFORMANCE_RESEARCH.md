# Performance research for the one-minute pipeline

## Full-cohort evidence at T+9h20

The complete native-RNG GW/orthogonal pass averages **97.72 s** over 74 pairs; box/orthogonal averages **96.36 s**. The complete Sobol-time GW/orthogonal pass averages **93.89 s**, with DIR/OASIS/abdomen means **93.36/95.59/93.30 s** (use the machine-readable comparison for exact stage/cache data). The original shared recipe averages **169.62 s**. Execution and fixed recovery sampling provide the large speed gain; small timing differences between method cohorts also reflect geometry order, worker reuse and compiler cache. They do not establish a Sobol-specific runtime speedup.

The separate high-matmul, 4k-update/four-time-evaluation recipe completes all 74 pairs at **55.01 s** pooled mean, with dataset means **60.93/56.83/52.93 s**. It gives DIR F/R 2.96198/3.09201 mm, OASIS 0.811434 Dice and abdomen 0.435252 Dice. OASIS is 0.001353 below the original, so this is a speed/quality frontier rather than an accuracy-preserving replacement. Brain folds decrease on every pair; abdomen mean/worst folds decrease, with individual regressions retained in the full comparison.

It changes numerical training precision, optimization budget and temporal recovery sampling; inference resets to highest precision. It is an approximation/quality comparison, not a parity claim. Shared on-disk compiler caches are warm from the session, and cold process/shape setup is still included in each dispatched case. A machine with an empty compiler cache has an additional unmeasured startup cost. Full comparison and final selection are in the [research report](LONG_RESEARCH_REPORT.md). The development-stage evidence below records how the implementation evolved; use the complete-cohort numbers above for the final result.

## Seventh-hour retained implementation

The accurate full-step CUDA graph path is now available through opt-in `runtime.training_execution: "captured"`. It retains original per-call native CUDA random streams, highest FP32, full parameter gradients, checked LU, smoothing, trajectories, clipping and fused AdamW. The default execution and scientific preset remain unchanged. `native_siren_gw_orthogonal_5k.json` adds the candidate's local/global GW-NCC and orthogonal two-pair geometry. These method changes have separate quick4 evidence; they are not numerical-optimization parity claims.

Full accelerated reference validation now covers all 74 protocol pairs: DIR **113.65 s**, OASIS **104.89 s**, abdomen **105.00 s**, versus **198.52/163.93/165.61 s** for the original implementation. The accelerated reference uses the earlier bulk RNG ordering, cap-256 native recovery and 16 time evaluations. A new full pass validates native RNG plus the better GW/orthogonal method and eight time evaluations. Cold-worker peak-memory telemetry was fixed and tested through a newly spawned worker before restarting that pass; failed pre-training attempts remain recorded.

Keep spatial and temporal recovery sampling separate. Four versus eight versus sixteen fixed time evaluations, all with 64 total RK2 substeps, were tested on 14 original and 13 GW frozen checkpoints. With eight evaluations the maximum score changes were **0.00677 mm / 0.000570 brain Dice / 0.000399 abdomen Dice** for the original family and **0.00323 mm / 0.000404 / 0.000351** for GW. All PCG intervals converged. Four evaluations save another roughly 4–5 seconds but change some abdomen Dice by up to 0.00156; retain eight for the full candidate comparison. This is fixed temporal quadrature of the ordinary brightness-flow solution, with no adaptive recovery rule.

An early-small/late-large endpoint point schedule does not currently save pipeline time. Multiple static shapes add compiler/graph-transition costs: measured DIR training is about 134 s versus about 78 s at fixed 32k in the earlier captured family. Do not count saved FLOPs as saved runtime. A cuBLASLt preference check likewise gives no useful forward gain and slows the weight-gradient layout. Neither is promoted. The wider/shallow 3k experiment and its ordinary-width 3k control instead test time to quality without changing point shape during a fit.

## Live session evidence, 2026-11-14

The 32k-particle width512 profile shows that matrix multiplies dominate the traced step. The high matmul mode reduces combined loss/backward21.84→18.07ms and frozen derivative evaluation29.90→20.72ms per262k coordinates. A real-input matched gradient comparison gives0.98% relative error at1k and6.32% at5k, despite nearly matching scalar losses. Its completed quick4 ablation gives DIR-Lab forward/reverse1.7955/1.8651mm, OASIS0.82506Dice and abdomen0.42378Dice. Per-case folding and matched full-reference timings still need review before promotion.

A three-product TF32 prototype gives roughly1.5e-7 relative matrix-output error against a sampled FP64 reference, but is slower than the existing highest-precision matmul. A bounded12–18-setting tiling/split-K follow-up also loses: best measured times0.58 versus0.30ms for32768×512 by512×512,0.19 versus0.076ms for10240×512, and0.66 versus0.28ms for the512×32768 weight-gradient shape. Do not substitute this kernel. This closes the plain tiled prototype; it does not establish that all tensor-core implementations are slower.

Two bounded native-PCG mixed-shape checks show roughly0.13ms/iteration, with unit-weight/static alternatives within8e-8 relative output error. The historical slow graph has not appeared. Monitor the full reference as its worker sees more shapes.

The full DIR-Lab reference takes about17–20s in recovery on quick4 and94–105s on the large volumes. A fixed coarse recovery-sampling prototype keeps original-voxel derivative/velocity units and spacing-weighted PCG, then converts its temporary maps to the original evaluation grid. This tests a controlled sampling approximation of the same equations. It needs frozen-checkpoint comparisons on all three datasets, both-direction TRE, folding, PCG convergence and cleanup checks before selection.

The first successful execution interaction uses an unrolled SPD3 LDL solve with double intermediates, fused trajectory decoding and CUDA graph capture. Matched real-input loss/backward falls24.84→16.07ms; relative complete parameter-VJP difference is8.3e-7, with unchanged highest matmul precision. LDL alone loses24.84→26.38ms, while adding the fused decoder gives20.57ms. The original solve plus decoder gives19.67ms but fails graph capture at `aten._linalg_check_errors`, which synchronizes the stream. Thus the solver change earns its place by enabling capture. Synthetic symmetric solve/VJP checks pass through condition number1e6. An isolated12-fit quick4 trial now measures complete-case savings, score/folding parity and persistent-worker memory before use in subsequent research.


The accurate native solve can also be captured by using `solve_ex(check_errors=False)` plus an asynchronous check of its status. This keeps FP32 LU arithmetic; the real-input full-VJP difference was about5e-7 and the captured modular objective took16.54ms. One compiler boundary around the complete loss reduced this to15.15–15.50ms. A further experiment captures backward, clipping and fused AdamW, and generates sampling inputs in512-step banks. The bank preserves the marginal crop, endpoint, directional-particle, query and time distributions while changing their RNG draw order. It therefore requires a registration comparison as well as an algebra check.

The first complete-step graph trial succeeded on one case and failed on11 later cases: automatic dynamic-shape compilation constructed an unpinned CPU shape tensor inside capture. Those failures remain recorded. The static-shape retry has completed its first three DIR-Lab cases without that error; the first case took99.6s including77.0s training and16.5s recovery. The full transfer and persistent-worker checks are still running.

A compensated BF16 three-/six-product matmul prototype also lost on all three relevant matrix layouts. The three-product version gave roughly4e-6–8e-6 output error, but input-gradient/forward/weight-gradient times were0.369/0.117/0.418ms versus0.302/0.0875/0.2885ms for highest FP32. This prototype is closed; no approximate tensor-core kernel has been promoted.

## Complete-step capture and recovery cap, fifth-hour review

The static whole-step retry completed all 12 quick4 registrations: DIR forward TRE **1.79788 mm**, OASIS Dice **0.824173**, abdomen Dice **0.427629**, with mean complete-case times **111.8/109.3/108.1 s**. The first dynamic-shape failure is retained as an unsuccessful implementation, rather than omitted from the evidence. A native-RNG implementation now captures the original per-call sampling sequence inside the CUDA graph: each mask-endpoint graph replays the appropriate generator offsets, while all losses, clipping and fused AdamW remain live. Twenty-four sampled rows match the ordinary sampler bitwise; 600 real updates pass at about **14.39 ms/update**. Its full quick4 results are DIR **1.81741 mm**, OASIS **0.824454**, abdomen **0.423555**, at **98.0/104.8/103.8 s** per case. Exact samples do not imply bitwise optimizer trajectories after fusion and changed floating-point reduction order.

The fixed **maximum recovery axis 256** passes 18 frozen-checkpoint comparisons. Small grids use the original recovery implementation directly, preserving all eight OASIS/abdomen quick4 scores. Large DIR recovery falls from roughly **95–105 s** to **21–28 s**; forward TRE changes range from **-0.0345 to +0.0206 mm**, with case 08 at the positive end. Derivatives and velocities remain in original voxel units; the coarse PCG uses the recorded original-voxel spacing, and temporary maps return to the original evaluation grid. This differs from uniform stride-two recovery, which lost OASIS accuracy. Geometry, analytical translation, full-gradient objective, zero-weight variants and scratch-cleanup checks pass. Sixty-two broader CPU checks also pass, with three intentional skips.

A persistent-worker deployment issue appeared after the ten full DIR cases: static joint-objective specializations exhausted TorchDynamo's cache and all remaining jobs failed before training. Retire only that objective code's obsolete specializations before compiling the next pair, then rerun the affected 64 cases under a new immutable source identity. Preserve the failed manifest. Shape diversity is part of deployment validation; twelve quick4 cases alone did not expose the limit.

The training-grid global-PCG experiment has a useful kernel result even though its registration scores are not a shared win. A one-block FP64 Triton primal/adjoint solver avoids unrolling hundreds of graph operations. Its corrected version checks the true internal residual before FP32 casting, and allows up to 512 iterations. The cast result has a finite representational residual floor on strongly rank-one cells, so an FP32-cast residual must not be confused with a failed FP64 solve. Frozen full-parameter VJPs agree with an FP64 dense reference to about **8e-7–2.4e-6**, and all 13 quick4/stress fits finish. The complete update costs about **15.43 ms**. Keep this as an algorithm/kernel finding; final shared accuracy does not justify changing the retained training estimator.

During captured fitting, GPUs show 99–100% utilization and roughly 40% memory-controller utilization, with about 575 W draw and 83°C. A relevant highest-FP32 matrix multiply sustains about 57 TFLOP/s. Utilization alone is not a measure of achieved arithmetic throughput. No hardware power or clock settings were changed.
