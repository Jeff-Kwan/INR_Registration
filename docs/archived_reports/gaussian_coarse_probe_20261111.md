# Coarse Gaussian smoothing does not preserve the dense approximation

**Decision: keep training on hold.** The fastest 16³ surrogate substantially loses
the previous dense Gaussian-versus-PCG agreement. Compilation improves runtime,
but does not resolve this spatial approximation error.

Frozen LPBA S02→S01 MSE+PD-LK and NCC+moments (.01)+PD-LK endpoints. Same three
representative times (.21875, .46875, .71875), seed 20261111 and 65,536 interior
voxel-centre samples as the dense probe. Foreground union has 17,322 points;
strong original-image edges have 4,331. No anatomical labels were used.

Pooled foreground vector metrics across three times (not mean per-point cosine):

| Lattice | Cosine vs PCG, MSE/NCC | Relative vector RMSE vs PCG, MSE/NCC | Cosine vs dense Gaussian, MSE/NCC |
|---|---:|---:|---:|
| Dense native grid | .944 / .932 | .330 / .364 | 1 / 1 |
| 16³ | .552 / .468 | 1.257 / 1.454 | .577 / .498 |
| 24³ | .730 / .658 | .787 / .931 | .760 / .708 |
| 32³ | .840 / .796 | .563 / .642 | .885 / .854 |

At 16³ RMS speed is 1.49/1.62× PCG and 1.63/1.82× dense Gaussian. Strong-edge
results show the same problem: PCG cosine .577/.473 at 16³ versus .947/.937 dense.
The 32³ speed ratio is near one, but direction and vector error remain materially
worse than the dense result. A matched RMS speed alone is insufficient.

Coarse fields were generated by the exact training prototype's analytic local
PD-LK solve and separable Gaussian, then trilinearly sampled at native sites.
Dense controls use the original native-grid local solve and SciPy Gaussian
(sigma=4 native voxels = 4 mm, reflect boundary, truncate=4), reproducing the
previous control. Both use c=4, eta=1e-6. Only scalar evidence is saved; dense
fields existed temporarily in memory. No RK2 trajectory or registration metrics
were evaluated. This is a field-fidelity probe, not proof that any particular
training objective cannot work.

Native array shape is 160×192×160. Lattice spacings are approximately
10.6×12.7×10.6 mm (16³), 6.9×8.3×6.9 mm (24³), and 5.1×6.2×5.1 mm (32³).
The 4 mm Gaussian sigma therefore spans only .31–.38 lattice units at 16³.
Local velocities already vary rapidly between native voxels; sparse evaluation
followed by filtering cannot reproduce smoothing those missing samples first.
The measurements are consistent with undersampling/aliasing and a poorly resolved
Gaussian. They do not isolate every contribution of discretization, boundary
extension or trilinear interpolation. Increasing coarse sigma would change the
physical operator; it is not an equivalent correction.

The independent compiler comparison shows gradient differences below .32% and
near-identical losses, so compiler numerical differences are far smaller than
this field discrepancy. At 32³ the compiled forward/backward pass remains about
322 ms. The present speed/fidelity tradeoff does not justify a training pilot.
Possible future work would need a better kernel-integral sampling strategy or
prefilter-before-decimation approach, each with its own cost and validation;
neither was implemented or tuned here.

All protected checkpoint/input file hashes remained identical. PCG converged at
2/3 MSE times and 3/3 NCC times; the MSE near-miss is the already documented slight
tolerance miss, so PCG is a qualified numerical reference. No training, optimizer
steps, saved maps/velocities, datasets changes or inference defaults changes.
Exact runner and local evidence are in
`results/gaussian_coarse_probe/20261111/`. The accompanying JSON retains per-time
PCG diagnostics, sums and both masks. No full cohort was launched.
